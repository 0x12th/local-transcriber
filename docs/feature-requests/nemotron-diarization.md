# Feature request: локальная диаризация Nemotron 3 на Apple Silicon

Статус: предложение к реализации. Этот PR меняет только документацию.
Источники и текущий код проверены 28 сентября 2026 года; запуск на M1 Pro,
качество русскоязычных записей и скорость в рамках этого PR не измерялись.

## Цель

Добавить опциональное определение «кто когда говорит» для локальных записей
встреч и интервью. Первый кандидат — `nvidia/Nemotron-3-Diarization` через
отдельный процесс `nemo-speech` из NVIDIA NeMo-Speech.cpp, с Metal на Apple
Silicon. Whisper и GigaAM сохраняются как движки распознавания текста.
Метки `speaker_0`, `speaker_1` обозначают голоса внутри одной записи, а не
имена людей; между записями их идентичность не гарантируется.

## Что есть сейчас

- [cli.py](../../local_transcriber/cli.py): `--speaker-count` сохраняется в
  метаданных; `--prompt-speakers` влияет на подсказку Whisper. Диаризации нет.
  Устройство ASR выбирается через `--device`; Whisper сейчас не запрашивает
  таймкоды слов.
- [transcript.py](../../local_transcriber/transcript.py): RAW отделён от
  представления, происхождение текста хранится в `raw_indices`. Whisper
  объединяет соседние сегменты только по временному разрыву, без проверки
  спикера; GigaAM сохраняет отдельные чанки.
- [outputs.py](../../local_transcriber/outputs.py): JSON имеет `schema_version=1`,
  `raw_segments`, `merged_segments`, `view_raw_indices`; выводятся два Markdown
  и JSON. Сериализатор отдельно проверяет происхождение чанков GigaAM.
- [README](../../README.md#results): таймкоды GigaAM приблизительные, относятся
  к чанкам длиной до 24 секунд. В одном чанке могут смениться несколько голосов.

## Проверенные возможности и ограничения

[NVIDIA описывает](https://huggingface.co/blog/nvidia/nemotron-diarization)
до восьми спикеров, пересекающуюся речь и обработку длинных записей с состоянием
между чанками. Диаризация возвращает активность голосов, а не слова каждого
участника: обнаружение двух голосов одновременно не позволяет автоматически
приписать каждому из них слова, распознанные ASR.

[Документация установки NeMo-Speech.cpp](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/main/docs/install.md)
предусматривает macOS Apple Silicon и Metal. Это подтверждает наличие пути
запуска, но не является проверкой конкретного бинарника с Nemotron 3 на M1 Pro.
Перед интеграцией требуется подобрать и зафиксировать совместимую версию
runtime и ревизию GGUF. Документация `main` может опережать опубликованный релиз.
При необходимости сборки из исходников фиксировать commit, а не плавающий `main`.

[CLI](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/main/docs/cli.md)
поддерживает отдельную диаризацию, RTTM, выбор устройства и локальный GGUF.
Выбирать Nemotron 3 явно: команда без модели использует встроенную модель
по умолчанию, которую нельзя автоматически считать восьмиспикерным Nemotron.
Применять потоковый проход с сохранением состояния даже для готового файла;
`--offline` означает отдельный full-attention режим для коротких записей.

## Предлагаемая интеграция

```text
Исходная запись ── Whisper / GigaAM ── RAW текст и таймкоды ───┐
       └── WAV mono 16 kHz ── Nemotron 3 ── интервалы голосов ─┤
                         сопоставление по общей шкале времени
                                  └── JSON / Markdown
```

Один небольшой `DiarizationProvider` и адаптер NeMo-Speech.cpp. Адаптер принимает
путь к аудио и параметры, вызывает CLI, преобразует RTTM в независимый результат
с интервалами `start`, `end`, `speaker_id` и сведениями о runtime/модели.
Сначала достаточно одного адаптера; система плагинов и локальный сервер не нужны.
Python-пакет NeMo не добавляется в обязательные зависимости. Уже существующие
зависимости Whisper, включая torch, этот запрос не меняет.

Подготовка WAV сохраняет начало записи, паузы и длительность. Нельзя склеивать
только речевые фрагменты без обратного отображения времени. Диаризатор получает
полную временную шкалу, а не независимые 24-секундные чанки GigaAM: иначе
идентификаторы голосов могут сбрасываться на каждой границе. Для первого варианта
этапы выполняются последовательно, чтобы не конкурировать за память Mac.

Вызов CLI — списком аргументов, без shell, с проверкой исполняемого файла,
кодом возврата, ограничением времени выполнения, отменой дочернего процесса и
очисткой временного WAV. Парсер проверяет формат RTTM, конечность времён,
`0 <= start < end <= duration` с документированным допуском округления и
допустимость идентификаторов. Пересечения разных голосов сохраняются.
Диагностика отделяется от машинного результата; ошибка не превращается в
пустую успешную диаризацию.

### Сопоставление с текстом

Для Whisper при включённой диаризации запросить таймкоды слов и сохранить их
в RAW. Отдельное представление со спикерами строить до существующей склейки
сегментов. Использовать документированное, детерминированное сопоставление по
временному пересечению; совпадение по времени является эвристикой, а не
доказательством того, кто произнёс слово. При смене голоса внутри слова,
пересекающейся речи или отсутствии достаточного покрытия сохранять неоднозначность.
Склеивать реплики только одного однозначного спикера; через смену спикера,
неопределённость или пересечение не склеивать.

Для GigaAM в первой версии сохранять исходный чанк и отдельно его интервалы
голосов. Единственную метку разрешать только при однозначном покрытии по
зафиксированному правилу. Если внутри чанка несколько спикеров, оставлять
`speaker_id=null` и кандидатов с признаком `ambiguous`, даже когда голоса
говорили последовательно. Не делить текст пропорционально времени, не
дублировать его для каждого голоса и не выдавать таймкоды чанка за таймкоды слов.
Точная разбивка таких чанков требует отдельного этапа выравнивания текста с
аудио; он выходит за рамки первой версии.

### CLI и совместимость

Ниже предлагаемый интерфейс проекта, **ещё не реализованные команды**:

```bash
just transcribe recording.m4a --diarization nemotron \
  --diarization-model models/Nemotron-3-Diarization.q8_0.gguf \
  --diarization-device metal

just gigaam recording.m4a --diarization nemotron \
  --diarization-model models/Nemotron-3-Diarization.q8_0.gguf \
  --diarization-device cpu
```

`--diarization none|nemotron` по умолчанию `none`. Отдельные параметры:
`--diarization-model`, `--diarization-device auto|metal|cpu` и
`--diarization-executable` для нестандартного пути к CLI. Они не меняют смысл
ASR-параметра `--device`: GigaAM может работать на CPU, диаризация — на Metal.
При явно запрошенном Metal и его недоступности сообщать ошибку, не подменять
устройство незаметно. В режиме `auto` записывать выбранное устройство либо
честно указывать, что runtime не позволяет достоверно его определить.

`--speaker-count` остаётся ожидаемым числом из метаданных. Оно не становится
командой «найти ровно N голосов» и не передаётся как выдуманный флаг внешнего CLI.
Для Nemotron запрос более восьми спикеров отклоняется с объяснением лимита;
режим без диаризации сохраняет прежнее поведение.

При `none` не проверять и не запускать `nemo-speech`, не скачивать новые модели,
сохранять существующие поля и формат `schema_version=1`. При включённой функции
использовать явно документированный `schema_version=2`, сохранив прежние поля
и смысл `raw_segments`, `merged_segments`, `view_raw_indices`. Добавить:

- `diarization`: статус `ok|failed`, проверенные сведения о runtime и модели
  (версия/ревизия, SHA-256 GGUF), параметры, устройство, предупреждения и
  исходные интервалы голосов;
- `speaker_segments`: отдельное представление с `start`, `end`, `text`,
  `speaker_id` либо `null`, кандидатами, статусом
  `assigned|ambiguous|unassigned` и ссылками на RAW-сегменты/слова;
- самостоятельный признак пересекающейся речи: несколько кандидатов у чанка
  GigaAM сами по себе не означают одновременную речь.

`transcript.md` сохраняет обычный текст. `transcript_timestamps.md` в новом
режиме показывает реплики и неопределённость из `speaker_segments`.
Старое представление остаётся доступным в JSON. Ссылки на RAW сохраняют
происхождение каждого фрагмента без поиска по совпадению текста.

Зависимость и модель устанавливаются явно, отдельно от транскрибации.
При запуске передавать проверенный локальный GGUF: индексированные имена
внешнего CLI могут автоматически инициировать скачивание. Проверить
офлайн-запуск после подготовки; аудио не отправляется в облако. Зафиксировать
источники, контрольные суммы и отдельные лицензии кода и весов в
`THIRD_PARTY_NOTICES.md` при реализации.

Проверки бинарника и модели выполнять до дорогого ASR. Если диаризация падает
после успешного ASR, сохранить обычный текст и RAW, записать `failed` с понятной
причиной, не публиковать частичные метки как полноценный результат и завершить
команду ненулевым кодом. Ранее созданные каталоги результатов не перезаписывать.

## Проверка на Mac перед реализацией

После явной установки совместимого runtime и проверенного локального GGUF:

```bash
nemo-speech --version
nemo-speech doctor
nemo-speech help diarize
nemo-speech model info models/Nemotron-3-Diarization.q8_0.gguf
ffmpeg -nostdin -n -i recording.m4a -vn -ac 1 -ar 16000 \
  -c:a pcm_s16le diarization-input.wav
nemo-speech diarize diarization-input.wav \
  --model models/Nemotron-3-Diarization.q8_0.gguf \
  --device metal --format rttm --output diarization.rttm
```

Это сценарий проверки upstream CLI, не отчёт об успешном запуске. Подтвердить
загрузку именно V3, обработку всего файла, валидный RTTM и Metal; одного
вывода `doctor` недостаточно. Зафиксировать runtime, commit при сборке,
модель/квантизацию, macOS, чип и объём памяти.

Измерить время холодного и повторного запуска, пиковую память, отдельно
диаризацию и полный конвейер. Отчёт должен содержать `RTF = время обработки /
длительность аудио` и качество на русскоязычных записях с 2–4 и 5–8 голосами,
перебиваниями, паузами и записью не короче часа. На размеченных отрывках
измерить DER с указанием обработки пересечений и допуска границ; отдельно
проверить ошибки сопоставления слов/чанков. Без эталонной разметки не называть
ручное впечатление измеренным DER. Результаты CUDA-бенчмарков не переносить
на M1 Pro. Численные требования к скорости и качеству определить по этому
прогону до реализации адаптера; сейчас результатов для их обоснования нет.

## Критерии приёмки будущей реализации

- [ ] Приложен воспроизводимый результат проверки Nemotron 3 на M1 Pro с Metal,
      зафиксированы runtime/GGUF, скорость, память и ограничения качества.
- [ ] Обычные Whisper/GigaAM команды и схема v1 не меняются при `none`;
      внешний процесс и новые загрузки отсутствуют.
- [ ] Оба ASR работают с независимым диаризатором; для GigaAM явно показана
      приблизительность атрибуции, для Whisper сохранены таймкоды слов.
- [ ] Проверены тишина, один голос, смена спикера внутри сегмента, длинные паузы,
      пересечения и неоднозначный чанк; текст не теряется и не дублируется.
- [ ] Реплики разных спикеров не склеиваются в speaker-представлении;
      RAW, временная шкала и ссылки на происхождение сохраняются.
- [ ] Ошибки модели/версии, отсутствие Metal, повреждённый RTTM, тайм-аут и
      отмена покрыты тестами; результат не маркируется как успешный при сбое.
- [ ] Тесты парсинга, сопоставления, CLI и сериализации работают без GPU,
      скачивания весов и внешней сети, на синтетических данных/заглушках.
- [ ] Проверены офлайн-запуск, инструкции установки, лицензии, помощь CLI;
      `just check` проходит. Приватные аудио и транскрипты в Git не добавляются.

Не входят в первую версии: замена Whisper/GigaAM на NVIDIA ASR, распознавание
имён людей, сопоставление личности между записями, разделение смешанных голосов
на аудиодорожки, live-режим, сервер и установка нескольких диаризаторов.
Если проверка Nemotron не удовлетворит согласованным требованиям, выбор другой
модели рассматривается отдельно; превосходство над pyannote здесь не заявляется.
